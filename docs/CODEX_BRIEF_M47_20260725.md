## 3. 作業1【最優先】遠征・暦・保存契約の整合

### 何が壊れているか(M46 §1a・全てコードで確認済み)

- `dungeonReturn`(帰り火)は末尾で無条件に `advanceSeason()` を呼び、**必ず1ヶ月消費**する。深度・成果による分岐なし。`store.ts:2183-2257`(末尾 `:2256`)
- 探索中の状態変化(被ダメージ・MP・戦利品・加護・踏破フロア)は `mutate`(`store.ts:221-229`)経由のみで、**`mutate` は保存しない**。
- `DungeonRun` は `GameData` に含まれずセーブ経路が無い。`continueGame` は無条件に `dungeonRun: null`(`store.ts:859`)。
- 出立中に `advanceSeason`(→`:699` `saveGame`)へ到達する経路は **帰り火 `:2256` と全滅 `:2773` の2つだけ**。
- **そして全滅は「解決」しても保存されない。** 自動進行の effect は `won` と `fled` だけを対象とし **`lost` を明示的に除外**する(`src/ui/Battle.tsx:603`)。`finishBattle()` への唯一の到達経路は敗北画面の手動クリック(`Battle.tsx:1047`「帰り火へ」)。**オートONでも同じ。**

**帰結**: 途中で閉じれば戦利品も被ダメージも月も巻き戻り、**敗北画面で閉じれば一族の死まで無かったことになる**。世代交代RPGの根幹である永久死が事実上 opt-out 可能。中心資源である18ヶ月(寿命24ヶ月 `types.ts:290` / 成人6ヶ月 `inheritance.ts:19`)の価値が、ゲーム内の判断でなく**アプリの閉じ方**で決まっている。

### 受入条件(機械検証可能)

決定論fixtureで**4経路**を実行し、**暦・HP・戦利品・死亡の4つが終了方法によらず同一**であること:
1. 正規帰還(帰り火)
2. 明示放棄(もしUIを作るなら)
3. 中断再開(アプリを閉じて `continueGame`)
4. **敗北画面での離脱**(`lost` で `finishBattle` 未実行のままリロード)

加えて: 通貨・item の複製0。既存の `tests/save*.test.ts` が緑。

### 設計上の注意

- **M45 P1-04(Dungeon checkpoint / 複製0の安全精算)が実装前提**。同じ `store.ts:859` と `DungeonRun` の save schema を触るため、**P1-04を先に実装するか、同時に設計すること**。別々に作ると衝突する。
- なお `DungeonRun` の永続化は M33 でユーザーが一度「意図的設計として維持・スキップ」と判断した経緯がある(WORKLOG M33)。**今回は M46 の発見(死の可逆性)により状況が変わったため昇格された**。この経緯を踏まえ、実装方針が M33 の判断を覆す形になる旨を commit message か WORKLOG に明記すること。
- 「深度比例で月コストを変える」かどうかは**別論点**。まず「終了方法によらず同一」だけを閉じる。月コスト自体の設計変更をしたい場合はユーザーへ提案し承認を得ること。

## 4. 作業2【次点】戦闘情報の信頼性保証

### 何が壊れているか(M46 §1b)

- **非署名敵の兆しは的中を保証しない**。`computeIntents` は実rngをクローンした一発サンプルで実rngを消費しない(`src/core/battle.ts:503-512`)。プレイヤー行動で実rngが進むため、表示と実行動がずれうる。
- 群れの長を討つと22%で行動が逃走へ上書きされるが、**兆しUIはこれを表示しない**(`battle.ts:469`)。
- **灯15%の警告に機構的効果が無い**。敵影速度に効くのは40%と0%(`engine.ts:808`)、戦闘補正は0%(`store.ts:1903`)、熱狂の発火は30%超(`store.ts:1874`)。**15%だけが機構と対応しないのに、UIでは最も強く警告される**(`Dungeon.tsx:61,100,314`)。

### 受入条件

- 固定seed 200件で、**確定表示した兆しの的中率100%**。
  - 保証する設計にするなら、予告と実行動が一致することをテストで固定。
  - 保証しない設計を選ぶなら、表示文言を「候補」「高確率」等に変え、DOM検査でそれを固定。**どちらでもよいが、嘘をつく表示を残さないこと。**
- 灯15%は「実害を持たせる」か「警告文言を実態に合わせる」かのどちらか。

### 順序について — **ユーザーの判断が必要**

M46 §5a に**未解決の対立**がある:
- **あなた(gpt-5.6-sol)の立場**: 必ず 作業2 → 作業3。虚偽予告のまま敵を強くすると読み合いでなく理不尽になる。
- **Claudeの立場**: 同一リリースで両方。勝率100%の戦いでは虚偽予告に実害が出ないため、単独先行では効果を測定できない。

**あなたが実装に入る前に、この順序をユーザーへ提示して選ばせること。** 勝手にどちらかで進めない。なお両者は「作業2を作業3より**後**にするのは危険」で一致している。

## 5. 作業3【要計測】中盤以降の難易度確認と学習曲線

### まず計測基盤を直すこと(これが本題)

M46 は「難易度曲線は最後の1戦まで平坦」と主張したが、**独立監査により撤回した**。理由:

- `tests/balance_sim.test.ts:132,153` は**全ボスに `bossParty()`(gen6精鋭・4人・def 92/78/70/66・HP 210/195/180/175・技持ち)を使う**。序盤ボス「苔ノ主」も終盤PTで殴っている。
- 同ファイル `:21` のコメントが謳う「装備gen3(中盤)」PTは**定義が存在せず、中盤は一度も測定されていない**。
- `simBattle`(`:60-81`)は毎回**全快・単戦**で開始し、以下を含まない: 戦闘間のHP/MP持ち越し(`mutate` は回復しない)/ 灯枯れ補正(`store.ts:1903` で `dark` 時 敵atk×1.4・HP×1.2)/ 主代わり補正(×1.5・×2.2)/ 語り部ease 0.78。

**つまり現在のsimでは中盤難易度を語れない。** ユーザーが依頼した「中盤以降の難易度確認」は、まずここを直すことから始まる。

### やること

1. **中盤PTを定義する**(装備gen3相当)。既存 `earlyParty()`(`:22`)と `bossParty()`(`:24-29`)の間を埋める。
2. **連戦simを1本追加する** — 1フロアぶんの連戦をHP/MP持ち越しで回し、灯消費と灯枯れ補正を反映する。単戦・全快の数値だけで結論を出さない。
3. その上で **中盤局面(中盤PT × 中盤帯の敵・エリート・地域主)を実測**し、素手policy と 現実policy(`smartAllyAction`、`:33`〜)の差を出す。
4. 結果を見てから、難易度調整が必要かを判断する。**必要と分かるまで敵の数値を触らない。**

### 受入条件

- 中盤局面で「素手policyの瀕死率 ≥ X% かつ 戦術policyの勝率 ≥ 95%」。**Xは計測後に決めてユーザーへ提示する**(先に決め打ちしない)。
- 既存の `tests/regression_m29.test.ts` の不変条件(非ボス個体の最終atk ≤ 最強ボスatk 等)を壊さない。
- `tests/balance_sim.test.ts` の既存assertionを壊す場合は、**なぜ旧oracleが誤りだったかを記録してから**変更する(M33で同種の是正を行った前例がWORKLOGにある)。

### 両者が明確に反対した方向(守ること)

**一律の強化と死亡率の引き上げには反対。** 全滅は複数人の永久死に直結するため、まず**非致死的な圧力**(HP / MP / 道具 / 戦利品 / 撤退判断)で差を作ること。
