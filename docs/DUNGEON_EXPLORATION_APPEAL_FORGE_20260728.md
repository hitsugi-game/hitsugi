# M55 探索体験強化「灯跡の夜藪」Forge正本

- 作成日: 2026-07-28
- 対象: `灯継ぎ -HITSUGI-` のDungeon探索画面
- 状態: 設計Forge合格。runtime・save・公開版は未変更
前提: GDD v3 §8.37 M54の`map-native`、探索ラスター0枚、M51の一遠征一seedを維持する

## 0. この正本の目的

探索画面を「暗いタイル上を移動する場」から、**灯で未知を読み、一族の痕跡を残し、危険と実りを自分で見つける場**へ変える。

豪華さを画像枚数、常時発光、粒子量で作らない。元のTileKind地図、灯、足元の反応、発見状態、地域固有の兆しを一つの文法にし、次の3点を同時に成立させる。

1. 3秒で「どこを歩けるか、何を目指すか、何が危険か」が分かる。
2. 10〜30秒ごとに小さな発見または判断があり、歩く行為自体に手触りがある。
3. 帰還時に「何を見つけ、何を残してきた遠征か」を一文で思い出せる。

## 1. 対象プレイヤーと画面の仕事

- 対象: 初見プレイヤーから、数世代・複数遠征を繰り返す継続プレイヤーまで。
- 画面の一番の仕事: **次の一歩を自分で決められること**。
- 二番目の仕事: その土地に来た実感と、灯が細る緊張を感じさせること。
- 三番目の仕事: 宝、怪異、稀相、主へ至る兆しを、答えではなく観察材料として見せること。

戦闘、報酬、家系、物語は探索の外部機能ではない。探索中の兆しと帰還後の記録を介して接続する。ただしM55では戦闘計算、報酬率、家系数値を変更しない。

## 2. 現行M54の診断

### 2.1 維持する長所

- 大型landmark・根画像を撤去し、地図形状が主役へ戻った。
- TileKind、collision、敵影、POIの対応が崩れていない。
- 濡土、浅水、轍、水紋、小さな岸葦というmap-nativeな画材が成立した。
- PC、mobile、1782×695で横overflowがなく、全戦闘オートや帰還処理も不変。

### 2.2 次に解く欠陥

- 地図外の暗部が広く、意図された未知より「何もない空間」に見える場面がある。
- 床面の大きな濃淡はあるが、主経路、脇道、危険、目的地の視覚的優先度が近い。
- 歩行しても足元・環境・地図状態の変化が少なく、移動が座標更新に見えやすい。
- 宝、祠、石碑、稀相は発見前後の段階が薄く、見つける楽しさより接触処理が先に立つ。
- 地域差は色、粒子、landmark設定に依存し、同じTileKind地図の別色版に見える危険がある。
- 「探索で見た兆し」と戦闘・帰還・次代の物語が画面上で十分につながっていない。

## 3. デザイン命題

### 3.1 探索の署名「灯跡」

プレイヤーが歩いた場所だけに、短時間残る足跡・水紋・倒れた草・灯の反射を描く。発見した重要地点には、その遠征中だけ消えない小さな灯印を残す。

灯跡は装飾ではなく、次の情報を兼ねる。

- どこから来たか
- どこまで灯が届いたか
- 直前に敵影が通ったか
- 帰路がどちらか
- 同じ場所を何度通ったか

灯跡が本作の一つだけの大胆な表現であり、他の演出はこれを邪魔しない。

### 3.2 固定palette

| 役割 | 色 | 用途 |
|---|---:|---|
| 境界の墨 | `#071016` | 未踏、壁、地図外 |
| 濡土 | `#273535` | 歩行主面 |
| 浅水 | `#0C2029` | 非歩行水面、深度差 |
| 継承金 | `#C9A86A` | 発見済み、帰路、記憶 |
| 生きた灯 | `#E8A33D` | 現在地、操作可能、灯の反応 |
| 危険の朱 | `#C73E3A` | 接敵直前、主、灯枯れ |

色だけで状態を伝えない。床形状、線種、動き、記号を必ず併用する。

### 3.3 情報階層

1. 主役: プレイヤー、歩ける開口、直近の危険または目的。
2. 判断材料: 敵影、POIの兆し、帰路、灯残量。
3. 雰囲気: 轍、水紋、葦、霧、蛍、環境音。

第3層が第1層より高コントラスト、速い動き、大きい面積を持つことを禁止する。

## 4. 地図の5状態

各tileまたはroomは、見た目だけでなく意味のある5状態を持つ。

| 状態 | 表示 | プレイヤーが理解すること |
|---|---|---|
| 未踏 | 墨の輪郭と低彩度の地相だけ | 何かあるが、答えは見えない |
| 気配 | 開口、音、蛍の流れ、地面の異常 | 調べる方向の候補がある |
| 発見 | 床材、POIの形、接続が明瞭になる | ここへ行ける／触れられる |
| 利用済み | 灯印、空箱、鎮まった水面など | 何を済ませたかが分かる |
| 危険化 | 朱の脈、逆流、沈黙、敵影の反応 | 今は安全でない |

未踏を完全な黒塗りにしない。地図の輪郭は残し、正解となるPOI種別と接続だけを隠す。

### 4.1 発見状態の所有とcheckpoint

発見状態の単一情報源は、optionalな`DungeonRun.discoveryV1`とする。engine内の`visited`は描画cacheであり、永続正本にしない。

```ts
interface DungeonDiscoveryV1 {
  version: 1
  visited: string[] // "floor:x:y"
  marked: string[]  // 発見済みPOI。同じkey形式
  traceIds: string[] // この遠征で帰還候補になった地域trace ID
}
```

- 配列は重複なし・辞書順で保存し、各keyのfloorと座標が実map内かsave guardで検証する。
- `visited`上限は全floorのwalkable tile総数、`marked`上限は全POI総数、`traceIds`上限は12。未知ID、範囲外座標、重複、上限超過は不正saveとして既存BAK復旧へ回す。
- engine生成時に`discoveryV1`を受け取り、`visited`とminimapを同じ集合から復元する。400ms pollはread専用のままにする。
- engineは新規tileまたはPOIを発見した時だけdeltaを`onDiscoveryChange`へ渡す。Reactはstoreのruntime `dungeonRun`へmergeするが、歩行1歩ごとにstorageへ書かない。
- 戦闘開始、特殊tile解決、階層移動、加護決定、明示休止・帰還という既存safe checkpointの直前に、未flush deltaをstoreへ反映してから`checkpointDungeon`する。
- safe checkpoint前にブラウザを閉じた場合は、位置・灯・発見をまとめて直前checkpointへ戻す。位置だけ新しく発見だけ古い、またはその逆を許さない。
- 旧saveで`discoveryV1`が欠損する場合は冪等migrationで、保存位置の周囲既定reveal範囲と`used`に含まれるPOIだけを復元する。過去に歩いた未記録経路を推測せず、未踏情報を開かない。
- floorごとの戦闘往復、同checkpointの二度再開、旧save migration、破損BAK復旧を決定論testで固定する。

## 5. 時間スケール別の探索ループ

### 5.1 0〜5秒: 次の一歩

- 入力後100ms以内に目的印を返す。
- 到達可能なら250ms以内に移動開始する。
- プレイヤー中心ではなく、進行方向1.2tile先までを安全表示領域へ入れる。
- 足元に灯跡が一つ生まれ、床材に応じた音と接触反応を返す。

### 5.2 5〜30秒: 一つの気配

- 次の開口、敵の兆し、POIの気配のいずれか一つを視界へ入れる。
- 同時に三つ以上の強い誘導を出さない。
- 近づくほど「音 → 地面 → 形 → 名称」の順に情報を開示する。

### 5.3 30〜120秒: 一つの判断

- 安全な主経路と、実りまたは危険を伴う脇道を提示する。
- 行き止まりは宝、石碑、焚火、怪異、景観署名のいずれかを必ず持つ。
- 灯、HP/MP、戦利品、敵影を見て「進む／戻る／寄り道」を選べる。

### 5.4 一階層: 緊張曲線

1. 門前: 操作と地相を短く読む。
2. 兆し: 地域固有の異変を一つ見る。
3. 分岐: 安全と実りを選ぶ。
4. 圧: 敵影、灯、地形で帰還判断を迫る。
5. 結び: 階段、主前、帰還のどれかで一文の記憶を残す。

### 5.5 一遠征: 記憶

帰還結果へ次のうち最大3件だけを残す。

- 最も深く進んだ階層
- 初めて見つけた土地の兆し
- 稀相または主の気配
- 持ち帰った代表的な実り
- 断念して残した場所

ログを増やし続けず、既存の帰還痕跡と地域怪異の文脈へ接続する。

## 6. カメラと画面構成

### 6.1 通常探索

- プレイヤーを画面中央から進行方向の反対へ5〜9%ずらす。
- look-ahead後にmap境界へclampする。
- 小mapは主人公でなくmap全体を安全表示領域中央へ置く。
- PCは地図占有率38〜76%、mobileは45〜82%を目安とし、地図外の平坦暗部を減らす。
- 移動中のzoom変化は禁止。room進入時だけ180〜260msで最大6%引き、全体関係を見せて戻す。

### 6.2 暗部

暗部へ大型画像を置かない。次の順で意味を持たせる。

1. 未踏地形の低コントラスト輪郭
2. 灯の届かない霧の密度差
3. 遠い音または一つの光点

説明のない平坦暗部率はPC 15%以下、mobile 20%以下を維持する。

### 6.3 全体地図

- 右上の「地図」で拡大し、現在地、発見済み接続、利用済みPOI、帰路を表示する。
- 未踏の接続、宝の中身、敵の正確な位置は表示しない。
- PC/mobileとも開閉1操作、Escape、外側click、focus復帰を満たす。

## 7. 歩行と環境反応

### 7.1 地面別反応

| 地面 | 視覚 | 音 | 残るもの |
|---|---|---|---|
| 濡土 | 足元がわずかに沈み、二本の細い轍 | 低い湿音 | 6〜10歩分の足跡 |
| 浅い水際 | 一つの水紋と灯の反射 | 小さな水音 | 1.2〜2.0秒の波紋 |
| 草 | 進行方向へ倒れ、ゆっくり戻る | 葉擦れ | 3〜5秒の伏草 |
| 石 | 短い硬質反射 | 乾いた足音 | 残さない |

### 7.2 動きの予算

- 同時に強く動く主役は、プレイヤー足元、危険兆し、発見POIのうち一つだけ。
- ambient poolは1画面24個以下。M54螢火では既存15個を基準とする。
- 新しい全画面filter、毎frameのDOM計測、毎歩の新規Texture生成を禁止する。
- reduced motionでは位置移動を止め、alpha、線、静止記号へ置換する。

## 8. POIの発見文法

POIを最初から名前付きアイコンで見せず、距離により開示する。

| 距離 | 表示 | 例 |
|---:|---|---|
| 6〜8tile | 地域固有の音または環境異常 | 水音が一度だけ逆に鳴る |
| 3〜5tile | 地面の筋、蛍、影の偏り | 蛍が脇道へ引かれる |
| 1〜2tile | 固有形と短い分類 | 「封じた箱」「濡れた石碑」 |
| 接触 | 操作と結果範囲 | 「調べる」「火を分ける」 |
| 利用後 | 状態変化と灯印 | 空箱、鎮まった水面 |

名前、希少度、報酬量を遠距離から確定表示しない。観察で期待を作り、接近で確信へ変える。

## 9. 宝・稀相・主の予兆

### 9.1 宝

- 未開封の宝は、同じ地域内では報酬tierによらず同じ反射、記号、音量を使う。
- 開封前の揺らぎは`regionId + runSeed + floor + 座標 + chest-cue`で決め、報酬抽選channel、報酬plan、item rankを入力に取らない。
- 観察で分かるのは「宝がある」「未開封である」まで。通常、良質、稀少の等級は開封後の結果演出で初めて示す。
- 箱の外形差を将来追加する場合も、地形由来の容器種別として扱い、報酬分布との相関を持たせない。

報酬抽選率は変えない。`chestCue()`相当の純関数がreward情報を引数に持たず、異なる報酬tierを代入しても開封前cueが同一であることをunit testで固定する。

### 9.2 稀相の魔性

- 金色の敵本体を常時強く光らせず、通常と異なる「環境の乱れ」を先に見せる。
- 逃げる方向へ草、水紋、星塵が引かれ、追跡可能性を示す。
- 捕捉後は既存の稀相戦、稀相dropへ接続する。出現率、逃走AI、drop率は変更しない。

### 9.3 主

- 主前室では通常ambientを減らし、地域固有の一つの兆しだけを強める。
- HPや攻略法は見せず、「この先は通常と違う」ことを輪郭、音、灯の挙動で保証する。

## 10. 地域固有文法

40地域を個別実装する前に、4地域pilotで異なる材料・動き・音・発見を検証する。

| pilot地域 | 主材料 | 署名反応 | 危険兆し | 記憶の一文 |
|---|---|---|---|---|
| 螢火の窪地 | 濡土・浅水 | 灯跡が水面へ二重に映る | 蛍が流れへ逆らう | 水没した灯の輪を辿った |
| 宵の森 | 落葉・樹影 | 踏んだ葉の色が一時残る | 葉擦れが敵方向だけ止む | 音の消えた枝道を越えた |
| 眠り地蔵の道 | 石・香煙 | 足音が一拍遅れて返る | 数珠状の影が道を塞ぐ | 名のない地蔵へ火を分けた |
| 星骸の谷 | 黒岩・鉱脈 | 灯跡が鉱脈線へ伝う | 星塵が上へ落ちる | 冷たい星脈を踏み越えた |

pilot合格後、40地域へ次の設定だけで展開できる構造にする。

- ground material 2種
- boundary line grammar 1種
- footprint response 1種
- ambient pool 1種
- POI hint 2種
- danger anomaly 1種
- footstep/ambient cue 1組
- return trace phrase 1本

画像差し替えではなく、地図の挙動差で地域を覚えさせる。

## 11. 物語との接続

- 地域怪異は既存`loreFrags → traceIntel → bossMikiri`を単一情報源にする。
- 探索兆しを見つけた時だけ短い一文を出し、長文Sheetで歩行を止めない。
- 同じ兆しの再発見では文を繰り返さず、環境反応だけを返す。
- 帰還時に最大3件を要約し、後の郷・図鑑・主戦で一つを回収する。
- 新しい第二の観察度、探索通貨、日課、期間限定報酬は作らない。

## 12. HUD再編

### 12.1 常時表示

- 灯、地名・階層、短期目的、現在手番に必要な隊員状態、地図、休止。
- 目的は動詞＋進捗で1行。「石碑を探す 0/1」のように書く。

### 12.2 条件表示

- 奉燈・血珠・経験、地相長文、帰還見込み、戦利品詳細は開いた時だけ。
- 帰り火は通常時に小型化し、灯40未満、瀕死、主撃破後だけ注意度を上げる。
- 小型化しても2操作以内、44×44px以上、keyboard focus、screen reader nameを維持する。

### 12.3 mobile

- 上段を灯＋地名＋休止、次段を目的＋地図に限定する。
- D-pad、隊員札、帰り火、safe areaの矩形交差0。
- 主要状態は縦844pxでscrollなしに読める。

## 13. 操作と失敗の扱い

- 到達可能tap: 100ms以内に灯点、250ms以内に歩行。
- 到達不能tap: 100ms以内に割れた灯点と短い理由。無反応にしない。
- 接触可能POI: 2tile以内で形、1tile以内で操作名を出す。
- 敵接触: 兆し → 接触 → 戦闘遷移を一つの方向でつなぐ。
- 帰還確認: 現在の実り、失うもの、月送りを確認する。脅し文句を使わない。

## 14. アクセシビリティ

- 色だけで床、危険、POI、利用済みを区別しない。
- reduced motion時はroom reveal、足跡の流れ、逆流を静止線へ置換する。
- 音は補助情報とし、重要な兆しは必ず形または文字でも示す。
- canvas外HUDはcontrast、focus、aria name、44px targetを満たす。
- 文字を地図へ焼き込まず、DOM側で倍率・言語・読み上げへ対応する。

## 15. 性能設計

- 同一floorの見た目は`runSeed + floor + 座標 + channel`から決定論生成する。
- footprint/rippleはpool再利用。生成上限を超えたら最古から再利用する。
- static Graphicsはmaterial単位にbatchし、tileごとのContainerを作らない。
- 性能gateは、repositoryで固定したPlaywright Chromiumと同じ計測scriptを使う。browser revision、commit SHA、runner名、CPU、GPU、OSを結果へ記録し、未知の「標準端末」という表現を使わない。
- PC profileはviewport 1280×720、DPR 1、CPU throttleなし。mobile profileはviewport 390×844、DPR 2、Chrome DevTools ProtocolのCPU throttle 4倍とする。いずれも音をoff、reduced motionをoff、同一初期save、同一runSeedに固定する。
- 計測scenarioは10秒固定とする。2秒静止、5秒連続歩行（camera追従、灯跡、足跡を発生）、2秒POI接近・発見、1秒拡大地図の開閉をscript化する。1回warm-up後に3回測り、各回のfps中央値と95 percentile frame intervalを保存し、3回の中央値で判定する。
- 合格はPC profileが55fps以上かつ95 percentile frame interval 20ms以下、mobile profileが30fps以上かつ38ms以下。さらに同じrunner・同じscenarioで保存したM54 baselineからfpsが10%を超えて悪化しないこと、pool上限超過0、新規の全画面filter 0を必要条件とする。
- CI runner差で絶対値が比較不能になった場合はbaselineとcandidateを同じjob内で連続測定し、相対劣化をgateに使う。実機観察は補助証拠であり、上記再現profileの代用にしない。
- 低性能時のambient半減では、床、歩行可能方向、危険、POI、帰路の判断情報を削らない。劣化順は浮遊塵、遠景の揺れ、足跡寿命、装飾反射とする。

- M51のrunSeedとcheckpoint決定論
- `maps.gen.ts`の地形生成。room archetype改修は別mission
- 新規ラスター画像、探索通貨、日課、期間限定要素

## 17. 実装順とgate

### Phase A: 読める構図

- camera clamp、map占有率、未踏輪郭、暗部率、HUD交差を修正。
- Gate: 3秒説明、暗部率、矩形交差、tap反応、PC/mobile。

### Phase B: 歩行の手触り

- 灯跡、足跡、水紋、伏草、地面別足音をpool実装。
- Gate: reduced motion、§15の固定PC/mobile profile、M54同job baseline比較、1入力1反応、視認性非劣化。

### Phase C: 発見

- `discoveryV1`、POI距離開示、利用済み灯印、宝・稀相・主の予兆。
- Gate: 見た目と実state一致、宝tier事前推測不可、未発見情報漏洩0、戦闘往復・同checkpoint二度再開・旧saveで一致。

### Phase D: 4地域pilot

- 螢火、宵、地蔵、星骸へ文法を適用。
- Gate: 地名を隠した静止画＋10秒動画で4地域を3/4以上識別できる。

### Phase E: 展開判断

- 初見8名と、一世代を遊んだ5名へ同じ課題scriptでlocal observationを行う。全員に同じPCまたは同じmobile profile、同じ初期save、別runSeedを割り当てる。
- 課題1: 開始3秒後に「今歩ける方向」と「今の目的」を指してもらう。初見7/8以上が両方正解。
- 課題2: 90秒以内に任意の脇道POIを一つ見つけてもらう。初見6/8以上が無介助で発見。
- 課題3: 危険兆しを一度見せ、「何が起きそうか」を選択肢なしで答えてもらう。初見6/8以上が危険接近または通常と異なる状態を説明。
- 課題4: 拡大地図から入口への帰路を指してもらう。初見7/8、一世代経験者5/5が正解。
- 課題5: 遠征後に「どんな場所だったか」を一文で答えてもらう。一世代経験者4/5以上が地域固有の材料または挙動を一つ含める。
- 重大操作摩擦は、20秒以上停止、到達不能地点へ3回連続入力、意図しない帰還、主要UIの見落としで進行不能、研究者の直接操作介入のいずれかと定義する。重大摩擦は初見8名中1名以下、一世代5名中0名。
- 失敗者数、分母、端末、所要時間、介助内容をそのまま記録する。n=8/5から効果量や一般人口への有効性は主張しない。
- 全5課題と重大摩擦gateを満たした地域文法だけを40地域へ展開する。一項目でも未達ならpilot修正へ戻り、一括量産しない。

## 18. 機械受入条件

| 分類 | 条件 |
|---|---|
| 構図 | PC平坦暗部15%以下、mobile20%以下、map外露出増加0 |
| 理解 | 初期3秒で歩ける方向・短期目的・直近危険を説明できる |
| 入力 | tap印100ms以内、移動250ms以内、到達不能も100ms以内に反応 |
| HUD | PC/mobileで主要矩形交差0、横overflow 0、主要target 44px以上 |
| 発見 | 未踏POIの種別・中身漏洩0、利用済み状態の誤表示0 |
| 決定論 | 同checkpoint再開で地図状態・兆し・POI hint一致 |
| 性能 | §15の固定10秒scenarioでPC 55fps・p95 20ms以下、mobile 30fps・p95 38ms以下、M54比10%超悪化0、pool上限超過0 |
| 安全 | reduced motion、音なし、keyboardのみでも必要情報を失わない |
| 回帰 | 全Vitest、lint、data、closure、manifest、production build green |

## 19. 主観Forgeルーブリック

各5点、全軸4以上、blocking 0を合格とする。

1. **世界観固有性**: 他のdark fantasyへ流用できない「灯・血脈・継承」の探索になっている。
2. **探索動機**: 次の一歩、寄り道、帰還の判断が自然に生まれる。
3. **操作明瞭性**: 何が歩け、危険で、触れられ、済んだかを迷わない。
4. **地域展開性**: 大型素材量産なしで地域差を作れ、4地域pilotから40地域へ段階展開できる。
5. **実装可能性**: 現行runSeed、checkpoint、render pool、UIへ矛盾なく接続でき、性能と回帰を検証できる。

blocking:

- 大型探索ラスターの再導入
- 未踏情報や報酬内容の漏洩
- 地形、collision、報酬率、戦闘計算の意図しない変更
- 同checkpoint再開で見た目や発見が変わる
- 必要情報が音または色だけになる
- PC/mobileいずれかで進行不能、主要UI交差、性能gate未達
- 40地域一括量産をpilot検証より先に行う計画

## 20. 見送る案

- 大型背景画像、根、施設cutoutを地図へ重ねる。
- 全tileへ枠線、noise、glowを足して密度だけを上げる。
- 常時大量の粒子、camera shake、blur、chromatic aberration。
- 宝、稀相、主の位置や中身を最初からminimapへ出す。
- 新しい探索通貨、energy、日課、期間限定bonus。
- 操作のたびに長文Sheetを開く。

## 22. 完了の定義

本正本の完了は、コード量や地域数ではなく次で判定する。

- プレイヤーが無介助で次の一歩を選べる。
- 歩行に毎回一つの意味ある反応がある。
- 地域を色だけでなく挙動で区別できる。
- 帰還後にその遠征固有の一文が残る。
- 操作性、決定論、性能、既存報酬を壊さない。
